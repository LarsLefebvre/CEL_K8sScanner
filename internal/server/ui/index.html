Policy playground

Write or tweak a CEL policy and evaluate it against the live cluster or pasted manifests. Nothing is saved.

How policies work. violations is a CEL expression returning true (one finding, using message) or a list(string) (one finding per element).
  • object: the resource. podSpec / containers: its pod spec and all (init/ephemeral) containers.
  • variables.<name>: named expressions from the policy's variables list.
  • cluster.clusterRoles[name], cluster.roles['ns/name'], cluster.serviceAccounts['ns/name'], cluster.networkPolicies, cluster.workloadCounts[ns].
  • rules.allows(verb, apiGroup, resource): RBAC check with Kubernetes wildcard semantics.
  • tactic, mitre and threatMatrix must reference real MITRE ATT&CK Containers techniques (e.g. T1611) and Kubernetes Threat Matrix paths (e.g. privilege-escalation/privileged-container); anything else is rejected.
  • Use a.?b.?c.orValue(x) for optional fields. Kind Workload matches top-level controllers and unowned pods.

Policies

Every check is a CEL policy mapped to MITRE ATT&CK (Containers) techniques and the Kubernetes Threat Matrix, grouped by ATT&CK tactic. Built-ins are embedded in the binary; organisation policies come from the kscan-policies ConfigMap.
